# Topic Planner — 글감 선정

글을 쓰기 전에 **무엇을 쓸지** 정한다. 기존 122편이 겨냥한 키워드 중 검색량이 확인된 것이 16개뿐이었다는 것이
이 스킬이 있는 이유다 (`ADSENSE_PROGRESS.md`). 감으로 고르지 않고 숫자로 후보를 좁힌 뒤, 숫자가 못 보는 것만 판단한다.

## 입력 (이미 있는 것만 쓴다)

| 입력 | 위치 | 비고 |
|---|---|---|
| 검색량 | `_workspace/keywords_volume.csv` | 30일 넘으면 `keyword_research.py volume` 재실행부터 |
| 안 쓴 주제 | `python -X utf8 keyword_research.py gap` | 티스토리 + `content/naver/` 제목 대조 |
| 추세 | `python -X utf8 trend_scan.py` → `_workspace/reports/trend_*.md` | 선택. 키가 없으면 건너뛴다 (개발자센터 신규 발급 2026-07-31 종료, `trend_scan.py` 주석 참조) |
| 블로그 검색 경쟁 | `python -X utf8 keyword_research.py serp 키워드 ...` | 상위 10개 중 최근 3주 글 수 + 우리 순위. 검색량 표의 '경쟁'은 **광고** 경쟁이라 이것과 다르다 |
| 범위·시즌 | `NAVER_GUIDE.md` 「주제 범위」「시즌 캘린더」 | 가져갈 것 / 버릴 것 |
| 이미 쓴 글 | `content/naver/NN_*.md` 첫 줄 제목, 카테고리 메모 | |

## 절차

1. **데이터 신선도 확인** — `gap` 출력 맨 위 경고(⚠ N일 전)가 있으면 사용자에게 알리고 재조회 여부를 묻는다. 묻지 않고 넘어가지 않는다.
2. **추세 리포트 확보** — 오늘 날짜 `trend_*.md`가 없으면 `trend_scan.py`를 돌린다. 키가 없으면 **발급을 안내하지 말고** 추세 없이 진행한다 — 사용자가 따라갈 수 있는 발급 경로가 지금은 없다. 이때 후보는 `keyword_research.gap_data()`를 `trend_scan.in_scope()`로 걸러 검색량순으로 뽑고, 캘린더 맨 위에 "추세 미반영"을 명시한다.
3. **1차 후보** — 리포트의 점수(월 검색량 × 경쟁 가중 × 추세 가중) 상위를 시작점으로 한다. 추세가 없으면 검색량과 경쟁만 본다.
4. **판단으로 거른다 (숫자가 못 보는 것)**
   - 블로그 검색 경쟁: 후보마다 `serp`를 돌려 결과를 캘린더에 적는다. 2026-10-07 기준 범위 안 상위 60개 키워드 중
     우리가 30위 안에 든 것은 하나(실업급여계산기 12위)뿐이었다 — **이 숫자로 '쉬운 키워드'를 골라낼 수는 없다.**
     이미 순위에 걸린 글과 같은 주제군인지, 실제 유입 검색어(사용자가 주는 유입분석 화면)와 닿는지를 함께 본다.
   - 시즌: 성수기 1~2개월 전인가 (`NAVER_GUIDE.md` 캘린더). 마감이 지난 주제는 뺀다.
   - 글로 해결되는 검색인가: 사이트·로그인을 찾는 검색, 조회 서비스 자체를 원하는 검색은 뺀다.
   - 카테고리 균형: 한 카테고리가 10편을 넘으면 감점, 비어 있는 카테고리는 가산.
   - 겹침: 이미 쓴 글과 키워드·검색 의도가 같으면 뺀다 (유사문서 위험).
   - 사실 확인 가능성: 정확한 수치를 공식 출처에서 확인할 수 없는 주제는 근거 수준을 같이 적는다.
5. **상위 5개를 `content/naver/_calendar.md`에 쓴다.** 항목마다 아래를 포함한다.
   - 키워드 / 월 검색량 / 광고 경쟁 / 블로그 검색 경쟁(`serp` 결과) / 추세 방향
   - 지금 써야 하는 이유 (시즌 또는 추세 근거)
   - 카테고리
   - 제목 구조 — 직전 글들의 구조·종결어미와 **겹치지 않는 것**을 고르되, 완성된 제목 문장을 예시로 박지 않는다
   - 필요한 이미지·계산·출처 (직접 확인해야 할 수치가 있으면 표시)
6. 사용자가 고르면 그때부터 글 작성으로 넘어간다 (`blog-writer` / NAVER_GUIDE 산출물 형식).

## 하지 않는 것

- 대출 금리비교·보험 비교견적·ETF·주식 종목 (NAVER_GUIDE '버릴 것') — 점수가 높아도 후보에 넣지 않는다.
- 밈·유행어를 블로그 글감으로 추천하지 않는다. 금융 주제 일관성(C-Rank)이 깨진다. 밈은 `sns_harness` Threads 훅 전용이다.
- 숫자를 만들지 않는다. 검색량·추세는 리포트에 있는 값만 인용한다.
- 이 스킬 파일에 완성된 한글 제목·훅 문장을 예시로 넣지 않는다 — 에이전트가 변수만 바꿔 복사해 글이 획일화된 전례가 있다 (`CLAUDE.md` 애드센스 섹션).

## 모델

후보 정리와 표 작성은 haiku 서브에이전트로 충분하다. 시즌·겹침 판단과 최종 5개 확정은 메인이 한다.
