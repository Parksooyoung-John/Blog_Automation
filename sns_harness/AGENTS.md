# SNS Harness Git 작업 규칙

## 원격 기준 작업

- 모든 변경은 `origin/main`을 `fetch`한 뒤, 그 최신 커밋에서 만든 `codex/` 브랜치에서 시작한다.
- `main`에 직접 커밋하거나 강제 푸시하지 않는다. 필요한 변경만 별도 PR로 올리고 병합한다.
- PR 전에는 `origin/main..HEAD`와 `HEAD..origin/main`을 확인해 원격에서 이미 반영된 작업을 다시 올리지 않는다.

## 남은 로컬 작업 처리

- `wip/sns-local-leftovers`는 잔여 로컬 변경을 보관한 브랜치다. 전체를 병합하거나 체리픽하지 않는다.
- 해당 브랜치와 원격 최신 `main`을 비교해 요청과 직접 관련된 줄만 새 작업 브랜치에 옮긴다.
- 원격에 이미 있는 미추적 파일이나 대규모 삭제·되돌림은 변경 대상으로 삼지 않는다.

## push-work 작업 폴더

- `push-work/`는 상위 저장소의 작업 폴더다. SNS 하네스의 커밋·푸시·병합 작업에 사용하지 않는다.
- 이 폴더의 `main`은 인수인계 시점에 원격과 크게 어긋나 있었다(앞 13커밋, 뒤 189커밋).
- 복구가 필요할 때만 읽기 전용 비교 대상으로 사용한다. 그 폴더에서 `pull`, `push`, `rebase`, `reset`, 커밋을 수행하지 않는다.
