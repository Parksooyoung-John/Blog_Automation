# Notion SNS 승인 큐 스키마

기존 블로그 발행 DB와 분리된 데이터베이스를 만들고 통합에 연결한 후 ID를
`NOTION_SNS_DATABASE_ID`에 저장합니다. 속성명과 유형은 정확히 일치해야 합니다.

| 속성 | Notion 유형 | 용도 |
|---|---|---|
| 이름 | Title | 블로그 제목 |
| 상태 | Select | 초안, 판매초안요청, 승인, 게시중, 게시완료, 보류, 오류 |
| 원문URL | URL | 출처의 canonical URL |
| TistoryID | Text | 레거시 이름으로 유지하는 출처 공용 중복 방지 키 |
| 원문발행일 | Date | 신규 글 판정 |
| 원문해시 | Text | 수정 감지 |
| 형식 | Select | single, thread |
| 첫게시물 | Text | 루트 게시물 |
| 답글1~답글4 | Text | 연속 답글 |
| 주제태그 | Text | `#` 없는 Threads 주제 태그 |
| 예약시각 | Date | 비어 있으면 다음 기본 슬롯 배정 |
| 게시시각 | Date | 실제 완료 시각 |
| ThreadsIDs | Text | 순서가 보존된 JSON 배열 |
| 오류 | Text | 마지막 검수·게시 오류 |
| 재시도횟수 | Number | 실패 횟수 |
| 판매플랫폼 | Select | 토스쉐어, 쿠팡파트너스 |
| 상품명 | Text | 사람이 확인한 상품명 |
| 상품URL | URL | 제휴 상품 링크 |
| 추천근거 | Text | 판매 답글에서 사용할 검증된 사실과 추천 이유 |
| 광고고지 | Text | 기본 고지문을 덮어쓸 때만 입력 |
| 상품해시 | Text | 승인 후 상품 정보 변경 감지 |
| Hook유형 | Select | 궁금증, 숫자, 실수, 비교, 질문, 경험/공감 |
| Hook문구 | Text | 첫 게시물 맨 앞에 배치되는 검증 대상 Hook |
| 블로그링크사용 | Checkbox | 네이버 원문 링크 포함 여부 |

`예약시각`에는 시간과 시간대를 포함하도록 설정합니다. 운영자는 초안 필드를 직접 수정할 수
있지만 480자를 넘기면 Harness 검증에서 게시를 중단합니다.

네이버 블로그 초안은 `Hook문구`가 첫게시물의 정확한 시작 문자열이어야 하며, Hook 강화
재생성 후에는 기존 승인과 예약이 제거됩니다. 모바일에서 내용을 다시 확인해 `승인`으로
변경해야 예약됩니다. 최근 9개 블로그 초안의 링크 포함 건수가 4건 미만일 때 다음 초안에
링크를 넣어 최근 10건 기준 링크 포함 비중을 30~40%로 유지합니다.

`TistoryID` 속성명은 기존 데이터와 자동화를 깨뜨리지 않기 위해 그대로 둡니다. 값은 티스토리
글이면 기존 숫자 ID(예: `165`), 네이버 글이면 출처 접두사가 붙은 `naver:{logNo}`(예:
`naver:224423197601`)입니다. 따라서 두 출처가 같은 숫자 ID를 사용해도 충돌하지 않습니다.
자동 예약과 게시 대상 조회는 `naver:` 키만 선택하므로 기존 티스토리 항목이 승인 상태여도
Threads에 새로 게시되지 않습니다.

상품형으로 만들 항목은 필수 상품 속성을 채우고 `판매초안요청`으로 변경합니다. Harness가
판매 답글을 만든 뒤 상태를 `초안`으로 되돌리고 예약시각을 비웁니다. 상품 정보가 승인 후
바뀌면 상품해시가 일치하지 않아 게시가 중단되므로, 다시 `판매초안요청`으로 변경해야 합니다.
`게시완료` 항목은 상품형으로 전환하지 않습니다.
